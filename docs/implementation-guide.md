# 下位モデル向け実装ガイド

このガイドは、1G1A の次回実装で迷いやすい部分をまとめたものです。実装はこの順番で進めると安全です。

## 1. 文字化けの解消

最優先です。既存の PHP と docs の一部に文字化けした日本語が残っている場合があります。

- HTML の `Content-Type` は `text/html; charset=UTF-8`
- `<meta charset="utf-8">` を出力する
- PHP ファイルは UTF-8 で保存する
- 画面文言は日本語として読み直せる状態にする

## 2. DB を共有イベント中心へ寄せる

推奨テーブル:

- `share_events`
- `share_event_photos`
- `share_access_logs`

既存の `posts` を使い続ける場合でも、意味は「QR表示1回の共有イベント」として扱います。

必要な保存項目:

- 選択された共有プロフィール
- 今回だけのコメント
- 今回だけの写真
- QR表示時の位置情報
- QR表示日時

## 3. 管理トップをモックに合わせる

`/dashboard` はスマホ利用を優先します。

- 上部に共有プロフィール名と表示名を併記した選択欄を置く。プロフィール数が増えても画面上に選択肢を並べず、選択欄の高さを保つ
- 選択を変えたとき、選択中プロフィールの画像（未設定時はアカウント画像）、公開表示名、見出し、紹介文を選択領域に表示する
- 選択中プロフィールのプレビューに編集ボタンを表示し、該当プロフィールの編集画面へ直接進める
- コメント入力・写真追加・有効期限
- オンライン送信後にQRを表示
- QR作成、共有プロフィール管理、基本プロフィール、共有イベント、使い方、新着情報、ホーム画面への追加、ログアウトは、ヘッダー左の `1G1A` ブランドから開くメニューに置く
- メニューは項目選択、メニュー外タップ、Escキーのいずれでも閉じられるようにする
- 共有イベント一覧は独立画面にし、各行の見出しに共有プロフィール名を表示して、ログイン時の削除対象になるまで期限切れ行も含めページングなしで並べる。期限切れ行は無効表示にする
- 共有プロフィール一覧の各カードに、そのプロフィールのイベント件数と「共有イベントを見る」ボタンを表示する。押すと対象プロフィールのイベントだけを一覧表示する
- メニューの「共有イベント」は、全プロフィール分の一覧を表示する
- QR画面の下部にダッシュボードへ戻るアイコンを置く
- 新着情報の閲覧はログインユーザー、編集は `admin` ロールに限定する
- QR作成の処理状態とエラーはスマートフォンでも常時見えるようにし、処理中はボタンの表示も切り替える
- 写真を選択しない場合の `UPLOAD_ERR_NO_FILE` はアップロード失敗として扱わず、QRを作成する

`QRを公開` を押したときは、共有イベントを作成して QR 画面へ遷移します。

初回ログイン時は、空の管理画面を見せずに、説明文つきの初期共有プロフィールを1件自動作成してください。ユーザーには「このサービスは会った相手に見せたい共有プロフィールを QR で渡すためのもの」という説明をログイン直後に見せると分かりやすいです。

イベント作成、コメント・写真の送信、プロフィール設定にはオンライン接続が必要です。オフラインでは Service Worker が保存した有効期限内の作成済みQR画面だけを表示できます。

- 共有イベント一覧に出ている期限内の最新5件のQR画面と画像をバックグラウンドでキャッシュする
- それ以外のQRは、オンラインで開いたときにキャッシュする
- オフライン起動時は期限内キャッシュ済みQR一覧を表示する
- 期限切れの画面はキャッシュから破棄し、表示しない
- 未キャッシュのイベントQRとゲスト向け `/s/{token}` はオフラインで表示しない

## PWA バージョンとセッション

- `VERSION` を現在のアプリバージョンの唯一の情報源にし、初期値は `0.0.1` とする
- リリースごとに `VERSION` を上げ、PWA起動時の `/version.json` 確認とService Worker更新に反映する
- PWAのログインセッションCookieは90日保持し、通常ブラウザーはセッションCookieのままとする
- 起動時の更新確認ができないオフラインでは、期限内のキャッシュ済みQR表示だけを利用可能にする

## 4. QR 表示画面

QR は共有イベントURLを指すようにします。

推奨URL:

```text
/s/{share_event_token}
```

QR画面で表示するもの:

- 大きな QR
- 短いURL
- 日本語メッセージ
- 英語メッセージ

位置情報:

- QR を公開するときに Geolocation API を呼ぶ
- 許可されたら緯度、経度、精度を保存する
- 拒否されたら何もしない
- QR 表示は止めない

## 5. ゲスト初回名前入力

`/s/{share_event_token}` で Cookie を確認します。

Cookie がない場合:

- 名前またはニックネーム入力画面を表示する
- POST 後に `guest_visitors` へ保存する
- `1g1a_guest_token` と `1g1a_guest_name` を Cookie に保存する
- 同じ共有イベント画面へリダイレクトする

Cookie がある場合:

- 名前入力画面を省略する
- 共有プロフィール画面を表示する

## 6. ゲスト公開プロフィール画面

表示内容:

- `○○さん、ようこそ`
- 共有プロフィールの表示名
- プロフィール写真（未登録時は公開表示名から生成した代替表示）
- 見出し
- 紹介文
- `今日のメッセージ`
- `今日の写真`
- `SNS・リンク`
- ログイン中の所有者プレビューでは、対象プロフィールの編集画面へ進むボタン

表示しないもの:

- QR
- プロフィール選択
- ログイン導線
- 位置情報

ゲストには編集ボタンや管理画面リンクを表示しません。ログイン中の所有者プレビューに限り、対象共有プロフィールの編集ボタンを表示します。

## 6.5. 共有プロフィールの SNS/連絡先リンク編集

共有プロフィールの編集画面では、登録済みのSNS/連絡先リンクだけをフォームに表示します。

- `＋ 連絡先を追加` を押すと、SNS/連絡先種類マスタから取得したアイコングリッドを表示する
- 未登録のアイコンを押すと、そのサービスの入力欄を編集画面へ追加する
- 登録済みのアイコンを押すと、該当入力欄へスクロールする
- 削除は入力欄側の削除ボタンで行う
- 保存すると、その共有プロフィールのゲスト画面に反映される

ゲスト画面では、登録済みのSNS/連絡先リンクをアイコングリッドで表示します。
アイコンを押すと、サービス名、コピー、リンク先へ移動を持つアクションメニューを表示します。
